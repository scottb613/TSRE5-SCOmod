TSRE GenX v0.11 Community Open-Testing Work List

======================================================================================================

SCOPE

TSRE GenX is a maintained development line of the TSRE route editor for MSTS and Open Rails route building. v0.9 delivered the Qt6/CMake modernization on master, v0.10 preserved the initial post-migration source checkpoint, and v0.11 carries the complete subsequent work into a community open-testing release on `tsre-scomod-wip`.

TSRE GenX stands on the combined work of Piotr Gadecki (GokuMK), the original author of TSRE5, who created its core editor, file, texture, and rendering systems and shared that invaluable work with the community; Eric Olesen (eric-from-trainsim), whose TSRE 8.006 development is the direct source line for GenX; and Peter Grønbæk Andersen, whose independent Qt6/CMake port provided important build, dependency, deployment, and DDS-loading references. Their work together made both the GenX improvements and the v0.9 modernization possible.

CURRENT RELEASE - v0.11 COMMUNITY OPEN TESTING
==============================================

   --- v0.11 Version Identity and Release Line ---
The application, CMake project, vcpkg manifest, Windows resource, development launchers, and public documents share the v0.11 identity. The existing v0.10 source tag and document snapshot remain immutable. v0.11 carries all completed post-v0.10 work into a new `tsre-scomod-wip` source tag and matching community executable package. CMake is the only maintained build path after removal of the retained qmake application and test projects, qmake prerequisite, and obsolete `.qmake.stash` rule.

   --- v0.11 Dynamic Track ---
Classic Flex has been retired. NextGen S-C-S-C-S Auto-Flex is the single Dynamic Track solver, the F1 panel presents that fixed mode without obsolete radio controls, and Object Selection supplies one editor-owned `NextGen Dynamic Track` category containing `Dynamic Track (Auto-Flex)`. Route and addon REF-file `dyntrack` entries are ignored so old external definitions cannot restore conflicting placement modes.

   --- v0.11 Rulers and Vegetation Preparation ---
Object Selection names the special tools `Ruler (water)`, `Ruler (vegetation)`, and `Ruler (grade)`. Water and vegetation use the same fifty-meter post layout, visible four-meter highway-cone-orange top cubes, Select-mode point movement, terrain snap on release, and Undo. The vegetation planning ruler retains its forest-green centerline and fixed magenta influence corridor fifty meters to each side, with bounded mitered joins and perpendicular end caps.

The magenta grade ruler accepts exactly two endpoints and reports Average Grade as per-mille, 1-in-X, angle, and percent using endpoint rise over horizontal run. Starting any water, vegetation, or grade ruler removes the existing special ruler while leaving the ordinary measurement Ruler independent. A seven-meter invisible selection volume surrounds each visible cube, and selection honors the clicked encoded point directly, falling back to terrain proximity only for genuine index collisions above sixteen points.

   --- v0.11 Instance Management ---
F12 General includes Instance Protection, defaulting to False. Enabling it preserves the single Route Editor restriction; disabling it permits multiple Route Editor instances. Shape Viewer remains unrestricted, and a blocked editor launch uses the shared stopped-action popup and sound.

   --- v0.11 New Route Coordinate Validation ---
New Route latitude and longitude fields accept up to twelve decimal places while enforcing the valid -90 to 90 and -180 to 180 degree ranges. Both the dialog and Route Loader verify numeric conversion, MSTS projection, and tile conversion before using the result. Invalid, unsupported, or out-of-range coordinates keep TSRE running and use the standard orange stopped-action popup instead of causing a crash.

   --- v0.11 ENG Parsing, DDS, ACE Texture Cache, and Memory ---
ENG/WAG token parsing now recognizes Unicode whitespace found in community Steam locomotive definitions without changing ordinary MSTS/Open Rails token handling. NVIDIA-style uncompressed DDS headers now treat `dwPitchOrLinearSize` as row pitch only when `DDSD_PITCH` is present, restoring valid 24-bit RGB and 32-bit RGBA rolling-stock textures while retaining DXT1, DXT3, and DXT5 support.

Repeated ACE references that resolve to DDS reuse one decoded texture by recording both the resolved DDS path and requested ACE name. Image Upgrade, Image Substitution, direct DDS behavior, and route TERRTEX exclusions remain respected. Cached reloads return the matched texture's real ID rather than texture 0, and temporary ACE, DDS, ordinary-image, paint-texture, and map-texture loader helpers are released after their work completes.

   --- v0.11 Interactive Markers and Shaders ---
All maintained Fog and Bloom fragment shaders bypass solid-color lighting during the selection pass so encoded picking colors remain exact. Original 3D marker cubes and directional pyramids use flat-face normals and the shared editor sunlight while the newer 2D symbols remain unchanged. Sound Source posts use the same shaded marker path, and New Symbols defaults to Off for fresh settings.

   --- v0.11 Release Automation ---
Two manually dispatched GitHub Actions define the guarded release path. Prepare TSRE GenX Release validates the selected branch head, requested version, release notes, public source layout, and confirmation before creating a new annotated tag; it can stop at a source-only checkpoint or create an unpublished draft release. Publish Approved TSRE GenX Release requires a protected `release` environment, verifies that the tag belongs to the selected branch, accepts only the named draft ZIP, compares its exact SHA-256, adds a checksum file, and publishes only after explicit confirmation. Existing tags and published releases are never replaced.

   --- v0.9 File Compatibility and Regression Evidence ---
A dedicated Qt5/Qt6 text-stream probe proved that the migrated UTF-16 serialization path produces byte-identical output, including the byte-order mark and non-ASCII text. This protects the established MSTS and Open Rails text-file behavior rather than replacing it with a new format.

TERRAIN SHAPING, PAINTING, WATER, AND SEASONS
=============================================

   --- Terrain Conforming Tools ---
The first major area was the [F] key terrain-to-track conforming tool. The old behavior produced very soft, wide terrain swells and did not make much visible use of the embankment/cutting sliders. I changed the terrain shaping logic so the track bed is held flatter and wider, with the cutting and embankment settings having a much stronger effect on the shoulder profile.

The goal was:

  - no holes under track when building embankments
  - no terrain encroaching on track in cuts
  - a flatter track bed
  - smoother shoulder transitions
  - much steeper cut/berm walls when the cut/embankment sliders are set high
  - more useful results at common settings such as 2-10-10-2

The F-tool track-width setting was also adjusted. The old width 1 behavior was effectively a single terrain data point, which was too narrow to be useful and could leave the result looking pinched. The low-end sizing now treats the first useful width more like the old width 2 behavior, so the 1/2/3 settings step through practical terrain-bed widths instead of starting with an unusably thin strip.

I also added a [Shift+F] smoothing pass for the selected track/ruler object. The smoothing pass was revised so it does not round the track bed into a trough or move the locked track-elevation points vertically. The important limitation is that MSTS terrain vertices have fixed horizontal X/Z positions, so the tool can only change heights; it cannot physically move jagged vertices sideways away from the track.


I added a selected-object [Ctrl+F] terrain conform pass. This is intended for faster controlled terrain shaping without relying on the pointer's nearest database line.

The workflow is:

  - select one track or road object
  - press [Ctrl+F]
  - TSRE finds that selected object's track/road database vector
  - TSRE applies the same F-style terrain conforming only to the portions of that vector that fall inside the current tile

This keeps the command understandable and avoids accidentally conforming terrain to the wrong nearby track or road. The current tile remains the break point so longer track or road runs can be handled a tile at a time.

I also added a new [F2] Height type called Conform DB for spot cleanup along track or road grades after the broader [F] key terrain conforming pass. Instead of flattening the whole brush to one height, each terrain sample under the brush checks the nearest track or road database line and moves toward that database elevation at that exact X/Z point. The brush is range-limited, while the existing brush size and intensity control the affected area and feathering.

   --- Tile Terrain Selection and Autopaint ---
I added [Alt+A] for selecting every terrain patch on the currently selected tile. The command requires a terrain patch to be selected first; when no terrain patch is selected, it quietly does nothing. With a valid patch selected, it selects the complete 16x16 patch grid, or all 256 terrain patches on that tile, so tile-wide terrain and texture operations can be performed without selecting patches one at a time.


The existing route painting workflow was expanded with tile-level commands instead of only object-by-object painting. The goal was to make repeated texture operations much faster without requiring a full route-wide processing pass.

Current tile-level tools:

  - Track on Tile
  - Roads on Tile
  - Water on Tile

These use the current brush texture, size, and intensity. Track and road tile painting now share the same implementation path; the only difference is whether the track database or road database is used as the vector source.

The water tool started as a simple water-patch painter, but that painted the 16x16 terrain swatches rather than the actual shoreline. It was then changed to detect the real water/terrain contour by comparing terrain heights against the tile water plane. This produces a shoreline-style feather around actual water edges, including shallow-water cases where terrain pokes above the water surface.

The water edge tool uses the pointer tile, so the tile being pointed at is the one processed.

   --- Automatic Water Helper ---
Water Helper now supports a route-scale workflow built around one persistent blue ruler. Each ruler point snaps to the terrain bed, and the scan follows every segment of the traced river or lake instead of loading one oversized rectangular region. The user controls water height above the bed and the number of neighboring terrain tiles searched.

The scan loads only the required detailed terrain corridor, samples each candidate patch at nine inset points, and flood-fills connected low terrain until it reaches raised shoreline or the configured boundary. Hard limits reject invalid coordinates, oversized corridors, unsuitable patch sizes, and runaway searches before they can exhaust memory. Status guidance reports the meaningful loading, scan, completion, and error stages without flooding the interface with repeated numeric updates.

Each affected tile receives four fitted corner elevations calculated in shared world coordinates so adjacent seams match exactly. Existing water edges are inherited only when they closely match the new surface, preventing unrelated water from pulling a new strip to the wrong elevation. Water flags and corner elevations are stored together in Undo.

One latched Water Ruler control now replaces the former Remove and Restart buttons. Activating it starts a fresh ruler; pressing it again or closing Water Helper removes the ruler. Process Water Tiles ends placement but leaves the completed ruler visible for review. Saved-ruler recovery remains bounded to the owning world tile.

   --- Waterbed Offset Brush ---
The F2 Waterbed Offset brush creates a consistent riverbed depth beneath water tiles whose four corner elevations form a slope. It accepts only a strictly negative offset and calculates each terrain sample from the locally interpolated water surface rather than using one flat tile-water height.

The brush retains the normal terrain brush size, intensity feathering, drag behavior, and Undo. Non-water patches, malformed tiles, missing buffers, non-finite values, and out-of-range samples are skipped safely. Its drag path uses one circular sample pass with cached terrain lookup and combined coordinate conversion, avoiding the former square Undo prepass and repeated quadtree work.

   --- Route and Tile TERRTEX Reset Tools ---
I added destructive-but-confirmed cleanup tools for terrain paint reset work.

Reset Route Terrtex Paint:

  - asks for confirmation
  - refuses to run when there are pending route changes
  - walks every .t file in the current route tiles folder
  - resets every terrain patch material to terrain.ace
  - replaces each .t file atomically
  - reports unreadable and failed-save tiles separately
  - deletes per-tile .ace/.dds files only after the matching tile saves successfully

Reset Tile Paint:

  - is available as a separate right-click menu item below Auto Paint
  - works on the tile under the pointer
  - refuses to run when there are pending route changes
  - resets that tile to terrain.ace
  - deletes generated ACE/DDS files for that tile
  - reloads the tile afterward

These tools do not delete shared/default textures such as terrain.ace or microtex.ace. They are intended as cleanup/reset tools after experimenting with lots of tile texture swatches. The route-wide reset now lives in the shared Hacks popup; the former F2 Terrain Utilities popup is reduced to Track Bias.

   --- Shared Hacks and Route Cleanup ---
Track, Static Object, and Terrain Patch properties now expose the same Hacks popup beneath a styled `Advanced` subtitle. Each launcher uses the established checkable orange active state. The active latch transfers when selection changes, and closing the helper clears the correct source button.

The Selected Track group contains Repair Junction, Repair Elevation, Remove Vector, and Remove Branch. These controls are disabled unless the current selection is a loaded track object, preventing a route repair from running against stale or unrelated selection data.

The Route Cleanup group contains:

  - Remove All Interactives
  - Delete Instances
  - Reset All TERRTEX
  - Water Tiles Off

Delete Instances is enabled for a selected static, gantry, or collision object. After a safe-default confirmation, it captures the selected type and filename, loads every route world tile, finds case-insensitive exact filename matches of the same object type, and removes them as one Undo operation.

Water Tiles Off scans every route terrain file and clears only the water-patch flag bits. Terrain heights, materials, gaps, and unrelated patch flags remain unchanged. Both route-wide terrain cleanup tools refuse to start with pending route changes, run non-cancelably after confirmation, commit tile files atomically, continue past unreadable or unwritable tiles, report read/save failures separately, and reload currently visible terrain when finished.

   --- Terrain Paint Presets and Rotation ---
I added a first pass at route-local terrain paint presets above Brush Settings in the [F2] terrain tools panel.

Each preset stores:

  - preset name
  - texture filename/path
  - brush size
  - brush intensity
  - brush shape
  - texture rotation

The UI has:

  - preset dropdown
  - Apply
  - Save
  - Remove

Presets are saved per route under the user's AppData TSRE folder, with a separate route-specific folder for each MSTS root/route combination:

tsre_terrain_paint_presets.json

This keeps route-specific paint workflows separated by route while avoiding extra editor-only JSON files in either the TSRE program folder or MSTS/ORTS route folders.


I added a full 0-360 degree texture rotation control under the [F2] terrain paint intensity slider. This is intended for seamless textures where angle matters, such as crop rows, plowed fields, and other directional ground textures.

The existing 0/90/180/270 rotation choices still work, but the slider allows finer control. A rotation of 0 remains the normal default texture orientation.

   --- F2 Terrain Editor Panel and Texture Workflow ---
The F2 Terrain Editor was restructured so the everyday terrain workflow is easier to read without losing the specialized controls. The panel is now organized into Texture Set, Edit Terrain Layers, Texture Preview, Presets, Brush Settings, Embankment Settings, and Advanced groups using the same compact charcoal/orange hierarchy and scale-aware control sizing as the other GenX editor panels.

Texture Preview now shows two adjacent 108x108 previews titled `MAIN TERRTEX` and `SNOW TERRTEX`. The active-side border follows the selected terrain set, while both sides are marked when Mirror Season is genuinely active. Each preview shows the exact selected source texture for its side and exposes the source filename in its tooltip. Missing, unreadable, wrong-format, or incomplete image data is reported as unavailable rather than allowing the seasonal resolver to display a misleading substitute.

Below the previews, `RECENT` is a six-texture bank arranged as two rows of three. A separate `BRUSH` swatch shows the texture actually assigned to the paint brush, so history and current paint state are no longer confused. The swatches use the same filename tooltips and readiness checks as the large previews.

The texture controls now include `Load...` alongside Pick and Put. Load accepts multiple files in one operation and validates ACE, DDS, JPG/JPEG, PNG, BMP, and TGA images before adding them to Recent history or assigning the brush. Successful loads select the texture and activate terrain-texture painting; failed files are named in the result instead of silently producing a broken swatch. `Hide generated tile textures` can filter generated TERRTEX tile swatches out of the selection list when the user wants to work only with source textures.

`Clear Recent` performs a complete, safe reset of this workflow. It clears the six-item history, active Brush swatch, both large previews, preview tooltips, and Mirror Season state. If the Texture tool or Mirror Season was active, their controls and brush state are turned off together so no invisible stale texture remains selected.

Route-local Presets remain directly above Brush Settings and retain texture path, brush size, intensity, shape, and rotation. Brush Settings use the clearer Height and Tool labels, format Height as `0.00`, disable it for tools that do not use it, enforce tool-specific ranges, and select the whole field value for immediate replacement. The database brush is named Conform TDB/RDB, and the additive tools are Add (Simple) and Add (Radius). Embankment Settings keep Size, Embankment, Cutting, Radius, and Set Pinpoint together.

Less frequently used controls remain outside the crowded main panel. F2 opens the pinnable `TRACK BIAS` helper for independent TrackDB and RoadDB height biases from -5.00 to +5.00 metres without changing database geometry. Route-wide TERRTEX and water cleanup now live in the shared Hacks popup documented above. `Reset Defaults` remains available on the main F2 panel.

   --- Seasonal Terrain and Texture Workflow ---
The old hidden settings-file seasonal editing workflow was replaced for terrain painting. The [F2] terrain paint panel now exposes the texture set directly, using Summer, Spring, Autumn, Winter, and Night choices. Changing the texture set reloads the currently loaded terrain, object shape textures, transfer textures, dynamic track textures, and generated forest/polyforest texture bindings so the editor display matches the selected season as closely as the route's available files allow.

The old startup warning, Settings-panel entries, and settings-file parser hook for the seasonal editing workaround were removed. Old `season = ...` and `seasonalEditing = ...` settings are now ignored/forced off, so older settings files cannot silently override the [F2] selector. Terrain painting and dynamic-track seasonal display now follow the active [F2] season selection instead of a hidden settings switch.

I also fixed transfer-object reload behavior so switching from Winter back to Summer invalidates cached transfer geometry/materials and rebuilds transfers against the active texture set.

To significantly speed up seasonal route building, I restored the [F2] Mirror Season button under Brush Settings as `Terrtex: Mirror Season`. TERRTEX painting only has two real output targets: the default `TERRTEX` folder and the snow `TERRTEX/SNOW` folder. Spring, Autumn/Fall, and Night can affect display/texture lookup for route objects, but TERRTEX mirror painting does not write to Spring, Autumn, Fall, or Night terrain folders.

Seasonal texture loading now follows an ORTS-style fallback model for route object, transfer, dynamic track, forest, and polyforest textures. When Spring, Autumn/Fall, Winter/Snow, or Night is selected, TSRE searches the matching seasonal subfolder first for each individual texture file, then falls back to the root texture folder if that file is missing. Object textures now try the active editor season first even when the old SD alternative-texture flags are missing or incomplete. The resolver also checks ACE/DDS alternatives, so a seasonal DDS can satisfy a material that originally referenced an ACE file.

For TERRTEX painting, Mirror Season mirrors only between default and snow. Painting while using a non-winter/default TERRTEX set mirrors toward `TERRTEX/SNOW`; painting while using Winter/Snow mirrors back toward the default `TERRTEX` folder. The same brush/autopaint trace is applied to the paired side, but the paired side must have a matching, decodable source texture with the same filename. Default painting uses the default source texture, snow painting uses the snow source texture. If either source is missing or invalid, Mirror Season automatically turns off, briefly reports `No Mirror`, clears the brush mirror state, and does not perform a one-sided operation under a misleading active control.

When Mirror Season is off, terrain painting still protects the opposite TERRTEX side from missing tile swatches. If painting creates a new per-tile TERRTEX patch in the active side, TSRE creates a matching placeholder patch in the paired default/snow folder only when that opposite patch does not already exist. The placeholder is copied from the route's paired-side `terrain.ace` when available, or from the bundled GenX content `terrain.ace` fallback. This prevents blank tiles if only one TERRTEX side has been painted, but it does not fake a mirrored texture paint.

A follow-up texture-cache bug was also fixed after testing on a large populated route. Generated objects such as forest regions may reapply their same material path frequently, so TSRE now invalidates cached texture IDs only when the material path actually changes. This avoids severe stutter and wrong texture reuse while still allowing seasonal texture refreshes to bind new material paths correctly.


I found a probable cause for occasional cases where 1024x1024 terrain texture swatches were saved back out as 512x512. TSRE's textureQuality setting could downsample textures when making them editable, and then the terrain paint save path wrote that reduced in-memory size back to the ACE file.

The fix prevents route-editing paint buffers from being downsampled before saving. In other words, textureQuality can still be useful for viewing/runtime, but should not permanently reduce editable terrtex files.

PERFORMANCE, RENDERING, VIEW, AND DIAGNOSTICS
=============================================

   --- Performance/Stutter Pass ---
I investigated severe editor stutters on populated routes, especially with forests. The main finding was that forest generation was happening lazily in the render path on the GUI/render thread. I added budgeted forest generation and stall logging so long bursts are reduced and easier to diagnose.

I also added a View menu toggle for Forest Region. When unchecked, TSRE skips drawing normal forest and polyforest regions, and also avoids generating their tree geometry while the layer is hidden. This gives route builders a quick way to work through dense routes without forest regions constantly filling the view or adding extra render/generation cost.

Related default settings were tuned for smoother editor startup/use:

  - lower default object/tile load pressure
  - reduced object lag burst behavior
  - disabled a few expensive/default visual options
  - mouseSpeed adjusted in the test dist settings

   --- Route Display Performance and Lighting ---
The Grade Symbols connectivity cache now uses a compact typed tile/UID key instead of repeatedly constructing strings. Tile loads and track-database edits invalidate the cache once at a safe boundary; rendering a previously unseen piece no longer launches a complete database traversal from inside the frame. This removes a real populated-route hot path while retaining correct orange, cyan, and red classifications after tile loading completes.

Pointer depth sampling now reuses its last OpenGL depth result until the mouse or camera actually changes, and it no longer queries the viewport state every frame. Control Panel object counts, camera position, and pointer position are emitted at a bounded update rate, while the panel itself skips rewriting unchanged coordinate fields. These changes reduce CPU/UI traffic and synchronous graphics readbacks without deliberately lowering the viewport refresh rate.

The normal-lit route shader now applies a warmer directional sunlight tint and a cooler sky-facing ambient tint for a less flat, more Open Rails-like preview. Unlit editor overlays retain neutral colors, and the change does not replace or reinterpret MSTS textures. Both legacy and OpenGL 3.3 shader copies are packaged because TSRE selects the appropriate external shader at startup.

F2 terrain texture previews now expose the source texture filename as a tooltip on both the large preview and Recent Texture thumbnails.

   --- View and Marker Tools ---
`View > Toggle All` replaces the old one-way Unselect All command. The first press remembers the current checked View actions and disables them; the next press restores exactly those selections. Compass is intentionally excluded so orientation remains available while overlays are temporarily hidden.

Marker label placement is deterministic after initializing the shared TextObj height offset and keeping `setHeight()` synchronized with its render position. Point markers now use four closely spaced vertical lines arranged as a small square, colored orange, cyan, or magenta from the MKR type value. The lines extend to three times the configured marker height so labels remain above surrounding scenery, while the original black camera-facing label treatment and sizing behavior are retained.

   --- Selection Diagnostic Clipboard ---
The right-click menu now includes `Edit > Copy Info` whenever an object or other editor item is selected. It creates a plain-text diagnostic block suitable for a forum post, bug report, or AI troubleshooting conversation. The common header includes the TSRE version and active route, followed by the most useful fields available for the selected type.

For world objects this includes the object class and filename, UID, tile and terrain-tile name, local position, quaternion, flags, detail level, and load/modified/flipped state. Track pieces also include section index, percent grade, and elevation radians. Terrain patches, track items, activity objects, consists, paths, and groups add their own relevant identifiers, positions, names, and member details where available.

STARTUP, SETTINGS, SESSION, AND SAVE SAFETY
===========================================

   --- Startup, Root Selection, and Session Restore ---
I added a startup guard so only one TSRE instance can run at a time. If TSRE is already open, a second launch now reports that TSRE is already running and exits before opening another editor window.

I also fixed the route-selection startup screen. When switching MSTS root folders, the route table was clearing cell contents but not removing the existing rows, which left blank rows/cells mixed into the display. The table now resets its row count before repopulating. Route loading was also tightened so it always loads from the route-name column, even if the selected cell is in the Last Modified column.

I added a proper TSRE icon to the Windows executable resource, using the icon stored in the local content folder. I also added a small AddShortcutDesktop.cmd helper, modeled after the SCO LIDEX shortcut helper, which creates a TSRE GenX desktop shortcut pointing at the local executable and using the same icon.


I added a Restore Last Session button to the first startup screen. Before a route is selected, the old full-width Exit button is now split into Restore Last Session and Exit. When TSRE closes normally, it writes a small lastSession.json file under the user's AppData TSRE folder. That file records the last route root, selected route, main window size and position, Control Panel position, and the editor camera tile, position, and rotation.

The intent is simple: if you were deep in a route, looking at a specific trouble spot, you can restart TSRE and return to that same working context without reselecting the MSTS folder, reselecting the route, and manually flying back to the same location.

The startup loader itself now opens centered on the primary screen. Independent compact `Pin` controls remember normal working geometry between sessions: the main window stores position, size, and maximized state, while the Control Panel stores its position. Unpinning returns a window to its normal default placement instead of leaving another group of manual position settings in F12.


I added `Open Route Folder` under the Route menu, placed with the other route-level commands. It opens the active route directory directly in Windows Explorer and reports a clear warning if the route folder cannot be found.

The startup window now presents the MSTS/ORTS root as an editable recent-root field beside a compact `Browse...` button. A path can be selected from the saved list, entered directly, or chosen from the folder dialog. TSRE validates that the selected folder contains the expected Train Simulator root structure before enabling route startup controls.

Invalid paths remain visible for correction with an inline explanation. Valid selections move to the front of the recent-root list without case-sensitive duplicates, retain their original path casing, and immediately refresh the available route table.

Normal startup now presents Main Load before constructing Route Editor, native OpenGL, and helper windows. Load and Restore use the same stable synchronous path while retaining editor reuse and return-to-loader behavior. PropertiesRuler initialization waits until its form has a parent, removing the transient standalone field artifacts that previously flashed during startup.

The public first-run and Reset baseline is portable: capped frame rate, 2 km object range, 4096-pixel map imagery, neutral UI scaling, bounded logs, no machine-specific paths, and conservative cleanup, database-rebuild, and world-file ordering. Main Load is the single normal startup path, and the editor consistently opens with Properties and Tools beside the viewport and Control Panel enabled.

   --- Startup Splash Rotation ---
The Route Loader, Consist Loader, and About window now share one splash image for the lifetime of each application session. The first splash request advances a persistent shuffled queue, and every later splash-bearing window in that process reuses the selected image. A new application launch advances to the next image, so each available splash receives equal time before a new shuffled cycle begins. The cycle also avoids repeating the same image across a cycle boundary when more than one image is available.

Splash artwork is discovered at runtime from the active versioned `tsre_appdata` folder. Files beginning with `Splash_` are accepted in PNG, JPG, JPEG, BMP, and WebP formats. Adding, removing, or renaming matching artwork automatically resets and reshuffles the queue without a code change or rebuild.

The queue is stored in the user's local TSRE application-data folder as `splash-cycle.json` and is written atomically so repeated launch-and-close testing advances reliably instead of becoming stuck on one image.

   --- Route Session Reliability ---
Reopening a route in the same process no longer mixes traffic IDs into the activity list. Traffic-file deduplication is case-insensitive without changing filesystem paths, and invalid activity entries are skipped instead of being dereferenced.

Returning from Route Edit to Main Load now performs a complete route-session reset. It clears route-owned MKR/KML/GPX data, shared marker inventory, marker selectors, Undo history, selection, group/copy pointers, and Water Helper pointers before another route is chosen.

Every route initialization republishes its marker list, selects the route marker from the TRK route name, rebuilds Object Selection categories, refreshes consists, scopes services and traffic to the active route, and reloads car-spawner and OR weather-transition inventories. This prevents a reopened route from inheriting entries or UI state from the previous route.

   --- Settings Editor Cleanup ---
I reworked the F12 Settings Editor around practical sections such as General, Logging, Startup, UI, Camera, Rendering, Overlays, Objects, Terrain, Map, Cleanup, Advanced, and Consist. The legacy settings.txt path has now been retired. Settings are stored per Windows user as settings.json in the TSRE application-data folder, so a packaged editor can remain read-only and separate users do not overwrite one another.

The Settings screen writes JSON atomically and keeps a timestamped backup before replacing an existing file. A Reset to Defaults action also preserves the current JSON first. If settings.json is damaged, TSRE preserves the unreadable file with a timestamped corrupt name, creates a clean default JSON document, and warns the operator. This avoids the memory leaks and invalid child pointers encountered when trying to apply every setting by calling Game::Load again inside an active editor session; restart-and-restore remains the safe path for settings that require a fresh process.

The JSON migration retains the complete settings set, including the route-building defaults previously kept in the text file. Independent TrackDB and RoadDB terrain height-bias settings were added for conforming work without changing the saved database geometry.

The visible comment clutter was removed from the rows and replaced with full-sentence tooltips on the labels and controls. I also added a Key Assignments tab with a two-column, striped table so shortcuts are easier to scan inside the editor. The Settings Editor now uses the same dark visual treatment as the rest of the GenX interface.

The final F12 audit made the dialog reload current disk/runtime values whenever it opens and keep the F12/menu state synchronized after Save or close. It corrected MSTS Shadows, snapping radius, Load Activities, and server-auth fields; removed route-owned superelevation and duplicate helpers; and moved stale map guidance to the F3 provider workflow. Reset now clears map credentials and provider state to the true 4096-pixel defaults.

View Markers is applied during startup, including the View-menu check state and route marker display. Invalid or empty object/track and terrain-patch selection colors are rejected at startup and replaced with the established `#B612FF` and `#FFB612` defaults rather than being written back as blanks.

AppData housekeeping retains only the five newest timestamped settings backups and three newest damaged-settings diagnostics. Route-specific folders are created only when route state is written, obsolete empty folders are removed at startup, and crash-safe route database generations remain independently capped at five per route.

   --- Settings Restart and Interface Sounds ---
The F12 editor now places `UI Sounds` directly below `UI Scale`. The setting controls editor interaction feedback including placement/error/success sounds plus `SCOtic.wav` for radio buttons, checkboxes, combo-box selections, and chosen menu actions. Route Loader pushbuttons always play the normal press sound immediately, before route loading begins, so startup feedback does not depend on the saved UI Sounds state.

Menu-command feedback covers selections from the Route, Edit, View, Tools, Settings, and Help menus. Sounds are tied to deliberate operator input; programmatic toggles and status synchronization remain silent.

F12 now provides `Save, Restart and Restore`. It saves the displayed settings, checks the route's existing unsaved-item list, and refuses to restart while route, terrain, database, or activity changes are pending. With a clean route it records the existing last-session route, camera, and window state; relaunches TSRE; and restores that session through the same startup restoration path used by the Route Loader. The existing Route menu reload command remains available for settings that can safely change in a running process.

   --- Crash-Safe Route Key Files ---
Route saves now serialize the TrackDB group ([route].tdb, [route].tit, and route-local tsection.dat), RoadDB group ([route].rdb and [route].rit), and modified TRK file before replacing any of those live files. Each replacement uses a same-directory atomic commit with direct-write fallback disabled, preventing a failed write from truncating the prior route file.

Before commit, TSRE creates a complete per-route backup generation beneath the single application-data [atomicSaves] folder. Each route receives a name-and-root-hash subfolder so routes with the same name in different installations remain separate. A manifest records the participating files and their hashes. If any replacement fails, the transaction restores the complete prior generation. If TSRE or Windows stops while files are being committed, the next route load detects the unfinished manifest and rolls the group back before reading the route. The five newest successful generations are retained; failed and recovered generations remain available for diagnosis.

Save completion is now reported only after the coordinated key-file commit succeeds. A failure leaves the TRK dirty state intact, plays the established error buzz, displays a route-save error, and reports SAVE FAILED instead of the previous unconditional Saved status. This first phase covers the route-root database and definition files; world and terrain tile families remain candidates for a later phase.

  - `SCOclick.wav` plays only after a successful guarded object placement.
  - `SCObuzz.wav` plays only after a Place Guard placement failure.

   --- Place Guard ---
I added a Place Guard system to catch the most common accidental object-placement mistakes after TSRE performs its normal placement operation. The idea is to leave the old placement workflow intact, then validate what was just created. If the placement fails validation, TSRE automatically undoes the placement, flashes the Place Guard button red with `ERROR` for three seconds, and plays `SCObuzz.wav`. If the placement passes validation, TSRE plays `SCOclick.wav`.

The current rules are:

  - All guarded placements must finish on the camera tile or one of the eight immediately adjacent tiles. Anything farther away is rejected as a likely long-distance miscast.
  - Track-linked interactive objects, such as signals and other track/road database items, must be started with the pointer within 3 meters of the target track or road database line. This prevents clicking far away and having TSRE silently place the item on some distant nearest database point.
  - Track-linked interactive objects must also finish near their database elevation. TSRE samples the nearest database height around the placed object and rejects the placement if the object height is more than 10 meters away from that database height.
  - Normal scenery/static objects must be placed on loaded terrain and within 1 meter above or below the terrain surface.
  - Track objects and dynamic track are allowed a wider terrain-height tolerance because they can legitimately be above or below local terrain during editing. They are currently accepted from 50 meters below terrain to 100 meters above terrain.
  - If Place Guard is turned off from the Control Panel, these checks are bypassed and TSRE uses the normal legacy placement behavior.

This is intentionally a guardrail, not a new placement engine. It should catch the route-damaging mistakes: objects cast into the sky, objects dropped below terrain, and interactives being thrown onto a far-away database line.

MAP AND IMAGERY
===============

   --- [F3] Map Loading ---
I fixed an [F3] OSM Vector Map loading failure that was showing up as a no-connection message followed by a crash to desktop. The log showed TLS initialization failures before TSRE ever received valid OSM data. The test package now includes the current OpenSSL 3 runtime DLLs required by the MSYS2/Qt network stack.

Eric-from-Trainsim's 8.006m update supplied the starting point for explicit Google and Mapbox provider selection. I adapted that contribution to the GenX F3 workflow rather than importing the broader branch. OSM Vector remains available without an account or API key. Google, Mapbox, and Custom imagery can be selected and configured alongside the other F3 map tools, and each provider keeps its own URL, API key, and zoom-offset values so changing providers does not destroy the previous configuration. Map resolution moved into the same F3 configuration window, leaving no duplicate or empty Map tab in F12. The map loader labels the active imagery source, applies changes without an application restart, and only exposes satellite imagery when the selected provider has the required configuration.

The OSM loader was also hardened so failed HTTPS/HTTP/empty/non-XML replies are treated as no-data responses instead of being parsed as valid map data. That should return control to the editor instead of crashing.

The packaged map imagery resolution is now set to 4096. The OSM vector loader still requests the tile area in four smaller quadrants, but the final per-tile rendered map image is controlled by mapImageResolution. 4096 gives a much clearer tile map than the old 512 default.

DYNAMIC TRACK AND GRADE ENGINEERING
===================================

   --- Dynamic Track Flex ---
The familiar one-curve workflow remains available as `Classic Flex S-C-S` (Straight-Curve-Straight). For the broader `NextGen Flex S-C-S-C-S` mode, selected by default, I adapted GokuMK's newer TSRE5/TSRE5vc Flex work as the foundation, with credit to Goku for that source work and direction. The shared action is named `Auto-Flex` so its purpose is clear.

The old Flex diagnostic graph window is hidden by default because it was more distracting than helpful during normal route work. A settings flag remains available when the diagnostic view is needed. Packaged fallback Dynamic Track textures were also added so routes that do not contain the usual procedural-track texture files can still display Dynamic Track in the editor. The TSRE rendering remains an editor preview; Open Rails is still the final judge of runtime track appearance and behavior.

I also implemented the NextGen connection algorithms that evaluate Straight-Curve-Straight-Curve-Straight candidates, allowing up to two curve sections for compound alignments and full S-curve connections. Classic continues to restrict solutions to its established one-curve pattern. NextGen uses the solved Dynamic Track path length for elevation calculations when available instead of relying only on straight-line endpoint distance, producing more sensible joins when the endpoints are at different elevations.

   --- Dynamic Track Editing and Reliability ---
Flex completion now updates the object first and reports success afterward. On a successful solve, TSRE removes the old Dynamic Track entry from the track database and rebuilds it from the new sections before playing the success sound. This prevents the editor from retaining stale database geometry that can appear as endpoint gaps or duplicate-looking track-database markers after Flex.

Dynamic Track elevation changes now update both the applied object rotation and the serialized elevation value, keeping saved data synchronized with what is shown in the editor. Dynamic Track naming is also normalized across the property panel, reference selector, object list, and Recent Items list so the user-facing label is consistently `Dynamic Track`.

   --- Dynamic Track Connection Accuracy and Validation ---
The NextGen Flex work was taken through a second reliability pass after train testing exposed cases where a Dynamic Track object could look close in the editor but still contain a vertical step, a curve-to-straight kink, or only one valid database connection. The source and destination connections are now solved without depending on which end is selected first. The generated object, procedural mesh, and TrackDB vectors use the same world-space endpoint plane and tangent frames, including reverse-direction connections on climbing track.

The vertical profile between the two known endpoints is intentionally one physical plane. The panel's percent grade is derived from the endpoint rise over the solved path length; the intermediate displayed grade is not allowed to move either joint. Internal section boundaries are rebuilt on that same plane so transitions between straight and curved subsections do not introduce a train-visible bump.

Flex is transactional: the existing object and database record remain intact until a candidate has passed the complete validation set. Candidates are discarded when they backtrack, form an unintended U-turn, fail to make two solid endpoint joins, miss either endpoint or tangent tolerance, or create an invalid internal seam. Deleted TrackDB records are ignored during snapping, while fixed overlapping endpoints are preferred over ambiguous vector samples.

Classic and NextGen use this same Auto-Flex connection, grade-plane, validation, and TrackDB pipeline. Classic limits the shared solver to one curve in an S-C-S pattern; NextGen may accept two curves in S-C-S-C-S. The unreachable older two-click staged Flex function, its global staging variables, dead Route wrapper, and commented keyboard caller were removed so there is no hidden alternate path that bypasses the current safeguards.

The final test route was rebuilt and run in Open Rails across level-to-level, level-to-grade, and grade-direction-reversed connections. The physical joints and internal transitions were reported silky smooth in both travel directions. The yellow TrackDB guide is now rendered as a continuous world-space overlay with raised vertical markers. This corrects the misleading broken/pitched visual without modifying the verified physical track geometry.

   --- Dynamic Track Materials and Property Presentation ---
Dynamic Track material lookup now follows a single guarded path for procedural track and packaged fallback textures. It does not require an Open Rails track-profile parser or seasonal matching to provide a recognizable editor surface. Missing or incomplete route textures fall back safely without leaving invalid material pointers.

The selected-object visualization follows the actual Dynamic Track path instead of drawing a large rectangular object box. The F1 panel presents Grade in the same percent format used by normal track and reports section index, total calculated length, and active curve count. Its five editable sections are named First Straight, First Curve, Second Straight, Second Curve, and Third Straight, making the generated pattern readable without interpreting raw values. The section fields use the established vertical spacing, and Select and Place New share equal width in the object panel.

   --- Track Grade Editing and Lock ---
Track properties now open with Percent selected as the default grade unit, while Permille, 1-in-X, and Angle remain available. The labels distinguish grade units from the general movement/rotation adjustment sensitivity so the controls are less likely to be confused.

`Lock Grade` captures the selected track or road piece's physical percent grade and applies that grade to each newly placed track/road piece. The lock state and captured grade remain visible in the Track properties panel. Turning the lock off returns placement to the normal TSRE elevation behavior.

   --- Grade Helper ---
The Track properties panel now includes a separate `Grade Helper...` tool for building controlled vertical transitions one connected piece at a time. The helper shows Current Grade, Target Grade, Step Per Piece, and Next Grade in percent. It can snap beside the Control Panel or other editor windows and returns focus to the viewport when the operator starts, stops, or closes the workflow.

When Grade Assist is active, TSRE verifies that the next placement is physically connected to the previously selected track/road database endpoint and that the starting grade still matches the expected current grade. A disconnected or mismatched placement is automatically rejected through the existing undo/Place Guard path. Each accepted piece receives the calculated next grade, advances by no more than the requested step, and stops exactly on the target instead of overshooting it. Reaching the target changes the helper to a holding state and enables the normal grade lock at the achieved value.

The placement endpoint information used by this check is transient editor state only and is never written into route world files.

Opening Grade Helper clears an existing manual Lock Grade so the two placement workflows cannot compete. Reaching the requested target silently hands the achieved value back to Lock Grade. Automatic state changes remain silent; accepted placement uses the normal track-placement click, followed by the existing delayed completion chirp when the target is reached.

Grade Helper has its own `Pin`, which remembers only the helper's position. It never causes the helper to open automatically on the next session; the operator must still click `Grade Helper...` when it is needed.

   --- Grade Symbols Overlay ---
The View menu exposes the global `Grade Symbols` toggle. It is enabled by default, while the redundant Track properties checkbox and introductory viewport legend have been removed. When enabled, graded static track, road pieces, and Dynamic Track receive square, direction-aware symbols above the track:

  - orange: steady grade
  - cyan: a transition because the piece differs in grade magnitude from a connected neighbor at either end
  - red: a direct crest or gully warning where two graded pieces meet without an intervening level section

The transition rule deliberately does not classify grades as increasing or decreasing. Each non-level piece checks both connected ends, including connections that cross vector-node and junction boundaries. Any grade-magnitude mismatch is cyan regardless of database traversal, object origin, or the visible uphill direction. A direct meeting where both uphill arrows face toward the joint (crest) or away from it (gully) is red because proper construction needs a level separator. Nearby parallel track does not count as connected.

Each symbol is placed at the exact distance midpoint of the ordered TSECTION path and aligned to the local path tangent. This keeps the marker centered lengthwise and on the same centerline used to draw long curves. Multi-path shapes use their declared main route when available and otherwise average valid paths. Mirrored artwork keeps the marking readable from either face of reversed/POS-NEG-swapped pieces.

The overlay cache is invalidated by grade rotation and track-database refresh operations. Because world tiles load incrementally, a rendered track piece missing from the cache now triggers a rebuild. This prevents later-loaded pieces and their already-visible neighbors from remaining incorrectly orange after Grade Symbols initialize at startup.


The Grade Helper follows the Track properties Units selection for both target and step values. Permille, percent, 1-in-X, and angle modes use compact unit symbols. Required operator inputs remain visually distinct from current and calculated readouts, spin controls retain visible arrows, and redundant Grade Symbols controls were removed.

Track properties now presents its unit-specific grade value in one stacked row, eliminating the vertical gaps caused by hidden rows. Position and rotation values are explicitly read-only. A shared editor-panel style extends the same field background, normal font, editable/read-only border distinction, spin controls, and vertical spacing to the remaining object/property panels, activity tools, settings window, and editor popups. The Control Panel keeps its separate established styling.

ACTIVITY BUILDER AND PATH EDITING
=================================

   --- [F4] Activity Builder and TrackDB Viewer ---
F4 now opens a dedicated full-screen Activity Builder instead of relying on the old activity panel to provide path context. The same F4 shortcut closes it, and opening the workspace maximizes the available map area while keeping fixed Path Editor and Activity Editor controls on the left and context-sensitive path controls on the right. Paths are standalone route resources: a user can create, inspect, edit, clone, delete, and save a path without first creating or selecting an activity.

The central viewer reads the route TrackDB and renders the actual track graph at high resolution with antialiased, continuously scalable geometry. Curves, junction approaches, sidings, crossovers, endpoints, three-way junction data, and dense XTracks areas remain visible through deep zoom instead of collapsing into the broken low-resolution segments shown by the former preview. Rendering is clipped and simplified by scale so panning remains smooth across very large databases; junction symbols disappear beyond the useful inspection scale, while route-level reference markers remain visible for navigation.

Orange junction symbols are painted over path lines and retain a practical screen-space click target when zoomed in. Their appearance distinguishes default alignment, a route whose stored default is diverging, and a switch thrown away from its default. Selecting a junction exposes its TrackDB node, pins, available exits, and chosen route so the operator can understand the switch state before changing it.

   --- Standalone Path Creation, Validation, and PAT Writing ---
`New Path` clears any previously displayed path and begins a route-level path with its own name and description. `Place Start` snaps the start to the TrackDB, `Reverse Start` changes the initial travel direction, and `Place Endpoint` fixes the desired destination after the preview has flowed across the route. Existing paths open through an explicit centered selection placeholder so no path is silently chosen merely because it is first in the list.

Selected control points can be removed with the Delete key, and path deletion, cloning, editing, and saving are guarded against the empty-selection and stale-selection crashes found during testing. Path display states, colors, and draw order are summarized with the completed session behavior below.

`Check Path` validates continuity, direction changes, switch transitions, alternate routes, and control-point order before writing. `Save Path` produces an MSTS/ORTS-compatible PAT file in the route's PATHS directory, including the path metadata and supported reverse, wait, overlap, and siding information. This replaces the former workflow of building a path in Open Rails Track Viewer and only selecting it later in TSRE.

   --- Natural-End Water-Flow Routing and Live Switches ---
Path construction now behaves like water on the TrackDB graph. After a start is placed, the preview follows the currently aligned route through each junction and continues to the natural end of track. Placing an endpoint corks that flow at the chosen location. Throwing any reachable switch removes the endpoint, recalculates from the affected junction, and resumes the flow until the operator places the new endpoint.

Switches remain live throughout editing; changing one does not require a separate throw mode or force the operator to rebuild the path. Recalculation retains the valid prefix, recomputes the affected continuation, verifies every junction alignment along the replacement route, and restores the previous switch state if the requested route cannot reconnect. A failed operation flashes a red message for three seconds instead of leaving a partially broken path.

The graph search accounts for crossovers and later valid reconnection points rather than stopping at the first geometric crossing or nearest turnout. Passing routes can therefore be shortened or lengthened at the same turnout, and their full chain of switches is checked during every recalculation.

   --- Reverse, Wait, Overlap, and Passing-Path Operations ---
Reverse points can be added to the active route, including after changing the initial direction. The outgoing path is recalculated in the reversed direction while the already-traversed portion remains intact. A reverse point can be selected and deleted safely; the dedicated removal action remains available where the extra path-state checks are useful.

Wait points support either a duration in minutes and seconds or a wait-until clock time in hours and minutes. The chosen operation is attached to a selected location on the path and written with the path data. Square selectors replace small round radio indicators so the active wait mode is legible in the dark interface.

The Advanced section adds ORTS Extended AI shunting operations using the same path wait-point records. `Blow Horn` stores a selectable one-to-ten-second horn duration. `Uncouple Cars` records whether the front or rear of the train is retained, how many cars including locomotives remain, and the pause after uncoupling. `Join / Split` joins the nearby train and continues the shunting move, while `Request Pass Red` requests permission for the AI train to pass the next red signal. These operations require the Open Rails Extended AI shunting support identified directly in the panel.

Advanced points remain visible and understandable after placement and after reopening a PAT file. Their markers use `H` for Horn, `U` for Uncouple, `J` for Join/Split, and `R` for Pass-Red; ordinary duration waits use `W`, and clock-time waits use `T`. Selecting any marker displays its decoded operation in plain language rather than exposing only the packed PAT value.

Wait and advanced points are associated with a specific path leg and TrackDB vector. Before saving, TSRE reconstructs each leg, orders multiple points along their vector, verifies that none was left behind by a switch or reverse edit, and rejects the save if a point is no longer on the active route. The encoded operation is preserved in the normal MSTS/ORTS PAT control flags so saved points can be imported for later editing.

Track traversed a second time is shown in cyan without breaking the magenta main path. Passing sidings are designated as orange alternates between two valid main-path junctions, may coexist on one path, and recalculate when a controlling switch is thrown. The editor validates that an alternate can return to the main path; an invalid throw is rejected, the original alignment is restored, and the existing valid siding remains unchanged. Undo and redo cover the path-building operations so experimentation does not require starting over.

   --- Route Orientation, Markers, Labels, and Interactives ---
`Rotate 90` turns the route view for clearer working angles and screenshots while the north arrow rotates with the map; the default orientation remains north-up. Fit Route, Fit Path, tile grid, junction, marker, label, and interactive overlays can be toggled independently without changing the underlying route or path.

The marker overlay reads only the MKR file associated with the active route and limits route-level navigation flags to marker type 0. Those flags and their text remain useful as the view zooms out, while close-range labels scale for readability. Signals use paired green/red indications offset from the track, and stations, fuel points, water points, and other service interactives receive distinct selectable symbology instead of being indistinguishable TrackDB dots.

The viewer keeps switches and path controls above track and path geometry, and preserves separate toggles for marker symbols, labels, interactives, junctions, and the tile grid. This creates a usable route-planning map rather than a path line floating without geographic or operating context.

   --- Path Sessions, Repair, and Final Save Safeguards ---
New Path, Edit, and Clone now operate as explicit editing sessions. The path selector is locked so the active object cannot silently change underneath the controls; the active command and selection remain stable, and the right-side Path Controls dock appears only for that session. Save completes the session and restores normal selection. Cancel restores the selected path's captured metadata and geometry, and safely removes any temporary route entry or clone file created by an unsaved new or cloned session.

The Meta Data dialog requires a valid PAT filename/ID, display name, start label, and end label before Save Path can proceed. A saved filename remains read-only during later edits so activities do not silently lose their path reference. The dialog also preserves the MSTS/ORTS player-path flag. New paths remain out of the normal path list until their metadata is confirmed or a PAT file exists.

Save Path now rejects missing metadata, missing or coincident endpoint controls, discontinuous routing, unresolved reverse legs, misplaced wait/advanced points, and passing paths that do not reconnect correctly. PAT output retains the path flags and uses atomic file replacement. Editing an existing PAT reconstructs its main linked list, switch choices, reverse legs, wait/advanced operations, and passing routes before allowing further changes.

The map distinguishes the selected route, start and end markers, reverse points, all wait/advanced point types, and service interactives. Endpoint labels use the path metadata during both editing and saved-path display. The selected route receives a strong yellow emphasis, repeated track stays cyan, passing routes remain orange, and point/switch controls are drawn last with practical screen-space targets so they remain selectable over dense TrackDB geometry.

Path editing remains available when a PAT is stale, disconnected, deliberately open-ended, or contains an unreadable passing branch. TrackDB point, junction, vector, vector-node, and platform references are validated before use. Damaged geometry is skipped with a diagnostic warning; surviving endpoints remain selectable and deletable, stale overlays are cleared, and deleting the active PAT closes its session cleanly.

When only a passing branch is unreadable, a safe-default warning can omit that branch from the draft while preserving the intact main route and original PAT until Save Path is chosen. Switch feedback is also truthful: successful main or passing-path recalculations use the normal placement click, while rejected and trailing-point no-op throws restore the previous draft and use the error buzzer.

   --- Consist Editor Compatibility and Presentation ---
Consist Editor resolves normalized `.inc` paths through ordered ORTS and MSTS candidates while preserving valid parent-directory paths. Shared definition fragments remain out of rolling-stock lists while normal include parsing continues.

Preview overlays use one restrained caption size with ellipsis for long names and a compact type/unit marker. Unresolved stock receives a selectable, scalable, non-mirroring MISSING card with clear selection, Delete/context-menu removal, and right-click `Swap Missing with Selected Stock`, preserving the chosen replacement.

Consist and Shape preview background colors persist independently per user. CE popups use dimmed captions, compact spacing, role-accented controls, concise orange titles, and the shared red/yellow safe-default treatment for destructive or unsaved decisions.

Production cleanup releases consist source files and inserted include buffers automatically, removes dead CE and UnsavedDialog declarations, and preserves both CameraFree movement overload sets. Retired standalone command-line, startup-setting, IDE-preset, and batch launch paths, together with the obsolete CELoadWindow source and build references, were removed from maintained projects.

   --- Eric 8.006m Compatibility and Route Health Reporting ---
Eric-from-Trainsim's 8.006m rolling-stock work identified ORTS `.inc` files that use mixed slash styles and legitimate parent-directory segments. GenX now normalizes each complete include candidate with the platform path rules, checks the ORTS and MSTS locations once in a defined order, and records the path actually loaded. This replaces repeated include attempts and avoids Eric's experimental string substitutions that could change the meaning of valid newer paths.

Eric's route-listing idea was also adapted into a single explicit workflow under `Route > Create Route Health Report`. The command loads every route world file with automatic repair disabled, records unreadable files and missing assets, distinguishes valid and duplicate world/sound UIDs, checks TrackShape and SectionIdx definitions, handles the optional route skydome, and summarizes used scenery, object, and track-shape files plus encountered StaticFlags/object types. It writes `TSRE-Route-Health-Report.txt` atomically inside the active route folder and opens the same text in a resizable read-only window with Copy All and Open Route Folder controls.

The older automatic loose report files in the TSRE working directory were removed so there is one predictable report location and one user-facing command. Creating a report is diagnostic only and does not modify route content. Activity-file scanning was deliberately left unchanged because the Activity Editor is undergoing a separate full rebuild.
